# Wedge Hypotheses (máximo 5)

**Definición usada:** pequeña parte del mercado donde AVENTA podría ser especialmente valiosa **antes** de competir por todo el mercado.

**Ninguna es ganadora elegida.** Todas E1 salvo evidencia citada.

---

## W1 — Demand hunting para compras deliberadas

| Campo | Contenido |
|---|---|
| Problema | Necesito producto X con condiciones (presupuesto/tienda) y el feed no me lo trae |
| Usuario | Comprador con intención específica (no scroller casual) |
| Alternativa actual | Grupos chat; alertas keyword PD; search retailers |
| Gap | Chat caótico; alertas = match automático de supply, no «humano caza por mí» |
| Hipótesis | Un request board con respuesta ligada + notify supera grupos para ese job |
| Por qué AVENTA | Plaza + publish + ofertas ya existen en CONTROL (parcial) |
| Dificultad | Alta (loop, calidad, cold start) |
| Riesgo | Spam, irrelevancia, baja participation |
| Evidencia | E3 Plaza PARTIAL; INFERRED uso de grupos; DOCUMENTED alertas PD ≠ human hunt |
| Qué demostrar | Usuarios crean requests; reciben ≥1 respuesta útil; vuelven |

## W2 — Cazadores especializados por categoría/nicho

| Campo | Contenido |
|---|---|
| Problema | Ofertas de nicho (gaming, bebés, tools…) diluidas en feeds generales |
| Usuario | Fans de categoría + hunters especializados |
| Alternativa | PD categorías; foros; Discord/Telegram nicho |
| Gap | Feeds generales priorizan volumen mainstream |
| Hipótesis | Matching demanda↔cazador por tag supera scroll general para nichos |
| Por qué AVENTA | Tags/creator tags admin existen; Plaza podría etiquetar |
| Dificultad | Media-alta (liquidez por vertical) |
| Riesgo | Fragmentación; verticales muertos |
| Evidencia | E3 tags admin; HYPOTHESIS demanda nicho |
| Qué demostrar | Tiempo-a-respuesta y calidad en 1 vertical piloto |

## W3 — Trust / «¿está realmente barato?» asistido por comunidad

| Campo | Contenido |
|---|---|
| Problema | Duda si el descuento es real antes de comprar |
| Usuario | Comprador ansioso / ticket medio-alto |
| Alternativa | Votos PD; Keepa/históricos; reviews retailer |
| Gap | AVENTA tiene votos pero señal débil a baja escala |
| Hipótesis | Workflow de validación (precio + vigencia + fuente) diferenciable si se opera bien |
| Por qué AVENTA | Detalle + votos + comments ya en pipeline |
| Dificultad | Media; datos históricos caros |
| Riesgo | Copiable; sin datos = opinión |
| Evidencia | E3 price insight parcial; DOCUMENTED temperatura PD |
| Qué demostrar | Decisiones de compra con menos arrepentimiento / más confianza (survey) |

## W4 — Publish rápido desde tienda (supply edge para hunters)

| Campo | Contenido |
|---|---|
| Problema | Cazadores quieren publicar en segundos desde la página del producto |
| Usuario | Power publishers |
| Alternativa | Extensión/app PD; copy-paste |
| Gap | Velocidad + UX AVENTA extensión vs incumbente |
| Hipótesis | Mejor tooling de publish atrae supply que alimenta feed |
| Por qué AVENTA | Extensión «Cazar oferta» ya existe |
| Dificultad | Media (distribución extensión) |
| Riesgo | No es diferenciación durable; PD ya tiene app |
| Evidencia | E3 extensión; DOCUMENTED publish PD |
| Qué demostrar | Publishers eligen AVENTA por fricción, no solo por comisión |

## W5 — Señal de demanda agregada (inteligencia, no marketplace)

| Campo | Contenido |
|---|---|
| Problema | Nadie ve qué se está pidiendo (más allá de lo publicado) |
| Usuario | Cazadores, editores, (futuro) partners |
| Alternativa | Ninguna estructurada en PD (supply-first); search trends externos |
| Gap | Demand graph ausente en deal sites |
| Hipótesis | Agregar requests genera ventaja informacional / priorización de caza |
| Por qué AVENTA | `plaza_requests` es semilla de demanda explícita |
| Dificultad | Alta (privacidad, volumen, utilidad) |
| Riesgo | Datos escasos; abuso; no moat sin escala |
| Evidencia | E3 schema requests; HYPOTHESIS valor B-side |
| Qué demostrar | Cazadores actúan distinto con visibilidad de demanda |

## No-wedges (explícito)

- Solo unificar copy «Cazar» → mejora UX, no wedge.  
- Rewards money path → fuera de scope HSE-03 / frozen flags.  
- Competir head-on con Google Shopping en comparación de precio → sin datos/infra.
