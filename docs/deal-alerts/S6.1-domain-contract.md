# S6.1 — Deal Alerts Domain Contract

## 1. Purpose

Formalize how Aventa decides that a deal **may enter** the Deal Alerts system.

S6.1 defines **contracts only**. It does not implement matching, delivery, cron, DDL, UI, LLM, or money path.

## 2. Alertability authority

Alertability is **not** a new score.

Authority stack (fail-closed):

1. **S8** `OpportunityDecision === OPPORTUNITY`
2. **Price Memory / evidence** `historyReady === true`
3. **Evidence level** `history_backed` or `api_verified` (only with `historyReady`)
4. **Evidence Contract** rejects pure `WEAK` listing evidence
5. **DQE** when evaluated must not be ineligible (`dqeEligible !== false`)
6. Stable **fingerprint** + non-`unknown` identity
7. Observation **not stale** (default max age 24h)

Module: `lib/dealAlerts/alertability.ts` → `evaluateAlertability` / `evaluateAlertabilityFromOpportunity`.

## 3. DealDetected contract

Reuses `lib/dealIntelligence/dealDetectedEvent.ts` (`DealDetectedEvent`).

Deal Alerts extension (intersection, backwards-compatible):

```ts
DealAlertsDealDetected = DealDetectedEvent & {
  dealAlertsContractVersion: 'deal-alerts.v1'
  alertability: AlertabilityEvidence
  userScoped: false
}
```

Builder: `buildDealAlertsDealDetected` — never sets `publicationAllowed` true; never embeds `userId`.

## 4. Idempotency

Global key (no user):

`buildDealAlertsIdempotencyKey` → `da:{detectionWindowVersion}:{diKey}`

Conceptual: fingerprint + detection window/version (+ DI source/sale/observed bucket).

User→alert dedupe is **out of scope** until S6.3/S6.4.

## 5. AlertDecision contract

Results (exact):

`MATCH` | `SUPPRESS` | `DUPLICATE` | `STALE` | `INSUFFICIENT_EVIDENCE` | `NOT_RELEVANT` | `RATE_LIMITED`

Shape: `result`, `reason`, `dealFingerprint`, `dealDetectedIdempotencyKey`, `evidenceReference`, `detectedAt`, `evaluatedAt`, `contractVersion`.

Mapper: `evaluateAlertDecision` — encodes outcomes; **does not** run subscription matching.

## 6. AlertSubscription conceptual contract

Typed only — **no table / DDL / persistence**.

Fields: `userId`, `stores`, `categories`, `minimumDiscountPercent`, `notificationChannels`, `enabled`, `cooldownSeconds`, `dailyCap`, `contractVersion`.

Invariant: **subscription never implies per-user scraping**.

## 7. Caps

See `DEAL_ALERTS_SUBSCRIPTION_CAPS` in `lib/dealAlerts/constants.ts`:

- max stores / categories per subscription
- min/max discount %
- max subscriptions per user
- max notifications per user/day
- cooldown bounds

Validated by `validateAlertSubscription`.

## 8. Money-path boundary

`DEAL_ALERTS_ECONOMY_BOUNDARY` + `assertDealAlertsMoneyUntouched`.

Deal Alerts must operate with `MONEY_PATH_FROZEN=true`.

Forbidden dependencies (source-guarded): payout intents, rewards engine, settlement, commission/conversion writers, attribution click writer.

## 9. Non-goals (S6.1)

- DDL / migrations / tables
- Cron / outbox / Redis cooldown keys
- Delivery / email / push / new notification writes
- Matching algorithm / UI
- Second alert score / LLM authority
- Money path changes

## 10. S6.2 handoff

**S6.2 — Alert Decision Layer (algorithm)**

Implement real Decision Layer using these contracts:

- consume `DealAlertsDealDetected` / `AlertabilityEvidence`
- produce `AlertDecision` with full reason codes
- still **no** user fanout delivery (that is S6.4–S6.5)
- still **no** DDL unless contract review explicitly opens persistence for `deal_detected`

Contract version: `deal-alerts.v1`.
