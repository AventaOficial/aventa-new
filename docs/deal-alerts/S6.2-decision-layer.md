# S6.2 — Deal Alerts Decision Layer

## Purpose

Deterministic **Decision Layer** over S6.1 contracts.

Decides whether a detected deal may generate alerts and which subscriptions match.
**Does not send** notifications, email, push, or write money.

## Identity layers (critical)

| Layer | Key | Scope | Blocks fanout? |
|-------|-----|-------|----------------|
| **Opportunity identity** | product/deal fingerprint + `da:{dw.v1}:{diKey}` | Global detection | **No** — audit only if already seen |
| **Alert identity** | `alert:{hash(window, fingerprint, subscriptionId)}` | Opportunity × subscription | **Yes** — per-recipient dedupe / cooldown |
| **Delivery identity** | Deferred to S6.5 (`delivery:{alertIdentity}:{channel}:{attempt}`) | Outbox attempt | N/A in S6.2 |

**Rule:** Global opportunity idempotency must **never** collapse all users into a single suppress.
Fanout = many `Alert identity` rows for one `Opportunity identity`.

## Entry point

```ts
decideDealAlert({
  dealDetected,      // DealDetectedEvent | DealAlertsDealDetected
  alertability,      // AlertabilityEvidence
  subscriptions,     // DecisionSubscription[] (= AlertSubscription + subscriptionId)
  context,           // AlertDecisionContext (injectable)
  opportunityCategory?, // gap: not on AlertabilityEvidence — fail-closed if required
  now,               // injected clock
  recordMatches?,    // test harness only
}): DealAlertDecisionOutcome
```

## Gate order (explicit)

1. identity válida  
2. evidencia suficiente  
3. freshness  
4. relevancia (S8 OPPORTUNITY + alertable)  
5. DQE eligibility (`null` = not evaluated → pass-through)  
6. subscription enabled (+ malformed → SUPPRESS)  
7. store / category constraints  
8. discount threshold  
9. cooldown (context)  
10. frequency cap (context)  
11. global idempotency (**audit only**)  
12. alert-identity dedupe  
13. final aggregate decision  

## Outcomes

Same enum as S6.1: `MATCH` | `SUPPRESS` | `DUPLICATE` | `STALE` | `INSUFFICIENT_EVIDENCE` | `NOT_RELEVANT` | `RATE_LIMITED`

Aggregate:

- ≥1 eligible → `MATCH` + `eligibleSubscriptions[]`
- all duplicate → `DUPLICATE`
- all rate-limited → `RATE_LIMITED`
- otherwise no match → `NOT_RELEVANT`

## Context provider

`AlertDecisionContext` — cooldown / frequency / alert dedupe / opportunity-seen audit.

`createInMemoryAlertDecisionContext` — tests only; Redis-compatible interface later.

## Gaps (fail-closed, not invented)

- No `category` on `AlertabilityEvidence` → pass `opportunityCategory` or category filters fail closed.
- No persistent subscription store → caller supplies in-memory subscriptions.
- No delivery → `deliveryPrep` metadata only.

## Money path

`assertDealAlertsMoneyUntouched` — Decision Layer runs with `MONEY_PATH_FROZEN=true`.

## Non-goals

DDL, cron, UI, LLM, delivery channels, money writes.

## S6.3 handoff

`fanoutDealAlert` retrieves candidates via `SubscriptionCandidateIndex`, then calls `decideDealAlert` — it does **not** re-implement these gates. Delivery outbox remains S6.5.
