# S6.3 — Deal Alerts Fanout / Matching Engine

## Purpose

Given an opportunity already evaluated by S6.2 contracts, determine **which subscriptions** are eligible — at scale architecture — **without sending** anything.

## Pipeline (four layers)

```
Opportunity (+ AlertabilityEvidence)
        ↓
1. Candidate Retrieval   SubscriptionCandidateIndex.findCandidates
        ↓
2. Candidate Filtering   index prefilters (store/category/discount)
        ↓
3. Decision evaluation   decideDealAlert()  ← S6.2 only
        ↓
4. Fanout construction   matched / suppressed / duplicate (exclusive)
```

Never mix retrieval with decision gates.

## Identities (unchanged)

| Layer | Key | Role |
|-------|-----|------|
| Opportunity | fingerprint + `da:{dw.v1}:{diKey}` | Global detection; **does not** block multi-sub fanout |
| Alert | `alert:{hash(window, fingerprint, subscriptionId)}` | opportunity × subscription |
| Delivery | deferred S6.5 | alert × channel |

**No fourth identity.**

Fanout unit = `opportunity × subscription`.  
Future delivery unit = `opportunity × subscription × channel` (`channelExpansionDeferred: true`).

## API

```ts
fanoutDealAlert({
  dealDetected,
  alertability,
  candidateIndex,  // NOT "all users"
  context,
  opportunityCategory?,
  now,
}): DealAlertFanoutResult
```

## SubscriptionCandidateIndex

```ts
findCandidates(OpportunityCandidateQuery): CandidateSet
```

Query dimensions (existing contract only):

- store / merchant
- category (caller-provided; gap on AlertabilityEvidence)
- discountPercent (prefilter vs `minimumDiscountPercent`)
- optional `enabledOnly` for future scale

`createInMemorySubscriptionCandidateIndex` — tests only.  
Replace later with Redis/DB inverted indexes **without** changing `fanoutDealAlert` business logic.

## Complexity / scalability

| Anti-pattern | S6.3 stance |
|--------------|-------------|
| `for each opp: fetch ALL subscriptions` | Forbidden as primary path |
| O(users) per opportunity | Avoid via indexed `findCandidates` |
| In-memory full scan | Acceptable only in test harness with known small N |

Production path: index by store/category/threshold → candidate set ≪ universe → S6.2 evaluate candidates only.

## Non-goals

Delivery, DDL, cron, Redis prod, UI, LLM, money path.

## S6.4 / S6.5 handoff

- S6.4: subscription persistence + real index  
- S6.5: delivery outbox expanding `channels[]` per matched alert
